# 学习型 LLM 路由：实验报告


## 摘要

本实验在一个 OpenAI 兼容的多租户 LLM 网关中，实现并评估了一个三档级联的学习型路由器：本地 Qwen2.5-7B-Instruct-AWQ（vLLM）→ Gemini 3.1 Flash-Lite → Gemini 3.8 Flash。路由器在调用任何模型之前，只根据请求文本（TF-IDF + 逻辑回归）预测便宜的模型能否答对，并把请求交给第一个"有把握"的模型。阈值只在训练集上，通过嵌套交叉验证选定。

在 651 道未参与训练的题目上，与"全部使用 Flash"相比：

- **balanced 档**：成本降低 **45%**，平均延迟降低 **36%**，保留 **98.7%** 的准确率；
- **economy 档**：成本降低 **88%**，**45%** 的流量由本地模型处理；在同等成本下，准确率比按比例混用模型高 **4.0** 个百分点。

在训练中从未出现的学科上，路由器会自动把请求升级到强模型，质量不下降。基于这一发现，系统加入了漂移检测，能够把这类流量识别出来（PSI 0.86–1.51，正常流量 0.003–0.031）。

全部训练标签都通过网关自身收集（3 个模型 × 3,319 题）。

---

## 1. 引言与研究问题

不同 LLM 的价格相差一个数量级以上。按原价计算，Gemini 3.8 Flash 每百万输出 token 7.50 美元，Flash-Lite 1.50 美元，自托管模型的边际 API 成本为 0。但大部分请求并不需要最强的模型。如果能在调用之前判断出"便宜的模型就够了"，就能在质量几乎不变的情况下大幅降低成本。

这个判断必须足够便宜：如果为了路由再调用一次大模型，省下的钱和时间就被路由本身吃掉了。因此本实验只考虑在网关进程内、以毫秒级完成的轻量分类器。

本报告回答四个问题：

| | 研究问题 |
|---|---|
| **RQ1** | 只根据请求文本做决策的路由器，能否在保持质量的同时显著降低成本和延迟？ |
| **RQ2** | 哪种文本表示最有效（手工特征 / TF-IDF / embedding）？决策结构（级联 vs 多分类）是否重要？ |
| **RQ3** | 路由器遇到训练中没见过的领域时，表现如何？ |
| **RQ4** | 能否在线上自动发现"路由器正在处理它不熟悉的流量"？ |

## 2. 实验设置

### 2.1 模型与价格

| 网关模型名 | 实际模型 | 思考配置 | max_tokens | 价格（输入 / 输出，美元每百万 token） |
|---|---|---|---:|---|
| `local-qwen` | Qwen/Qwen2.5-7B-Instruct-AWQ，vLLM v0.11.0，RTX 5070 Ti 16 GB | 无 | 1024 | 0 / 0（边际成本，不含硬件和电费） |
| `gemini-flash-lite` | gemini-3.1-flash-lite | 关闭（budget 0） | 1024 | 0.25 / 1.50 |
| `gemini-flash` | gemini-3.8-flash | LOW | 4096 | 1.50 / 7.50 |

### 2.2 数据与划分

| 数据集 | 题数 | 类型 | 作用 |
|---|---:|---|---|
| GSM8K（test） | 1,319 | 数学应用题，答案为数字 | 代表"简单请求"，大部分模型都能答对 |
| MMLU-Pro（test，按学科分层抽样） | 2,000 / 12,032 | 14 个学科的 10 选 1 题 | 难度高，模型之间分歧大，提供主要的学习信号 |

划分方式：

- **ood**（246 题）：MMLU-Pro 的 law 和 history 两个学科整体留出，不参与训练，用来检验对新领域的泛化；
- **train / test**（2,422 / 651 题）：其余题目按 id 的 SHA-256 哈希值以 80/20 划分。划分只依赖 id，因此可复现，以后新增题目也不会改变已有题目的归属。


### 2.3 标签协议

- 每个模型对同一批 3,319 题各回答一次，标签为"是否答对"，不使用大模型打分；
- 请求**通过网关自身发出**，关闭缓存和 fallback，并校验响应头 `X-Gateway-Model`，保证每个标签都来自指定的模型；
- temperature 0，零样本 prompt，要求固定的答案格式（GSM8K 为 `#### <数字>`，MMLU-Pro 为 `ANSWER: <字母>`）；

## 3. 方法

### 3.1 级联路由

对除最后一档以外的每个模型，训练一个二分类器，估计 P(该模型答对 | 题目)。路由规则：

```text
请求 -> 同时计算 P(local 答对)、P(lite 答对)            （网关进程内，毫秒级，不调用任何 LLM）
     -> P(local 答对) ≥ τ ？是 -> local
                             否 -> P(lite 答对) ≥ τ ？是 -> lite
                                                       否 -> flash（兜底）
```

τ 越高，越多请求升级到强模型，质量更高，成本也更高。每个模型使用独立的分类器，新增一档时只需为原来的最后一档补一个分类器，已有的分类器不受影响。

### 3.2 特征与分类器

| 方案 | 文本表示 | 分类器 |
|---|---|---|
| handcrafted_lr | 17 个手工数值特征（长度、数字个数、数学符号、LaTeX、代码标记、疑问词等） | 逻辑回归 |
| handcrafted_hgb | 同上 | 梯度提升树 |
| tfidf_lr | TF-IDF，一元和二元词组 | 逻辑回归 |
| embedding_lr | gemini-embedding-001（3,072 维） | 逻辑回归 |
| tfidf_multiclass | TF-IDF | 多项逻辑回归，直接预测"能答对的最便宜模型"；按累积概率 ≥ τ 选择 |

### 3.3 阈值选择：只用训练集

```text
train（2,422 题）
  外层 5 折交叉验证：每道题都得到一个"训练时没见过它"的预测概率
    内层 5 折：选择正则化强度 C；TF-IDF 词表在每一折内部拟合
  在这些概率上扫描 τ = 0.00, 0.01, …, 1.00：
    约束：准确率 ≥ 全用 flash 在 train 上的准确率 − 允许的下降
    目标：交给便宜模型的比例最大
test、ood：τ 和模型全部确定之后，各评估一次
```

三个质量档位只是允许的下降幅度不同：

| 档位 | 允许比全用 flash 低 | 选出的 τ |
|---|---:|---:|
| high | 1 个百分点 | 0.92 |
| balanced | 3 个百分点 | 0.89 |
| economy | 8 个百分点 | 0.74 |

### 3.4 指标与基准线

- **准确率、总成本（原价）、平均延迟、各模型分到的流量比例**；
- **单模型基准**：全用 local / lite / flash；
- **凸包基准**：把三个单模型的（成本，准确率）点画在图上，取它们的上凸包。凸包上的每一点，都可以通过按比例随机混用相邻的两个模型得到。路由器只有高于凸包，才说明它确实"判断"出了哪些请求该交给哪个模型；
- **完美路由器（oracle）**：每道题都交给能答对的最便宜的模型，是理论上限。

## 4. 结果

### 4.1 单模型表现与理论上限

| test（651 题） | 准确率 | 总成本（美元） | 相对全用 flash 的成本 | 平均延迟 |
|---|---:|---:|---:|---:|
| 全用 local | 69.0% | 0 | 0% | 4.74 秒 |
| 全用 lite | 90.6% | 0.382 | 17% | 1.54 秒 |
| 全用 flash | 94.6% | 2.228 | 100% | 4.78 秒 |
| 完美路由器 | 95.4% | 0.516 | 23% | — |

全量数据上，三个模型在两个数据集上的准确率：

| | local | lite | flash |
|---|---:|---:|---:|
| GSM8K（1,319） | 91.1% | 96.6% | 98.0% |
| MMLU-Pro（2,000） | 51.9% | 84.0% | 90.4% |

两点观察：

1. **模型能力几乎是包含关系。** 在 MMLU-Pro 上，"local 错、lite 对"有 689 题，而"local 对、lite 错"只有 46 题。也就是说，local 能做的题，lite 基本都能做。这使得级联结构非常自然：问题简化为"便宜的模型够不够"。
2. **理论空间很大。** 完美路由器只花全用 flash 23% 的成本，准确率反而更高（95.4%），因为它也能利用少数"便宜模型对、贵模型错"的题。

### 4.2 RQ1：三个质量档位

**主结果**（test，τ 在 train 上选定，test 只评估一次）：

| 档位 | 准确率 | 保留 flash 的准确率 | 成本降低 | 平均延迟降低 | 流量分配（local / lite / flash） | 同等成本下比凸包 |
|---|---:|---:|---:|---:|---|---:|
| high | 94.5% | 99.8% | 19% | 17% | 0.5% / 35% / 65% | +0.8 |
| **balanced** | **93.4%** | **98.7%** | **45%** | **36%** | 3% / 63% / 34% | +0.9 |
| **economy** | **87.9%** | **92.9%** | **88%** | **47%** | 45% / 55% / 0.2% | **+4.0** |

![成本-质量曲线](benchmarks/router/results/three-tier.png)

*图 1：test 与 ood 上各方案的成本-质量曲线（τ 从 0 到 1）、单模型点、凸包与完美路由器。*

**回答 RQ1：能。** 路由器在三个档位上形成了一条连续的成本-质量曲线：

- balanced 档几乎不损失质量（保留 98.7%），成本降低近一半，延迟降低三分之一以上。节省主要来自把 flash 不必要的请求交给 lite；
- economy 档把近一半的流量交给免费的本地模型，成本降低 88%。在这个区间，路由器相对凸包的优势最大（+4.0 个百分点）：它能分辨出哪些请求本地模型就能答对；
- 一个旋钮（档位）覆盖了从"几乎全免费"到"接近全用 flash"的整个范围，调用方可以按请求选择。

### 4.3 RQ2：文本表示与决策结构

下表在 high 档的约束（允许低 1 个百分点）下比较五种方案（test，按原价计算）：

| 方案 | AUC：P(local) / P(lite) | 准确率 | 成本降低 | 同等成本下比凸包 |
|---|---|---:|---:|---:|
| handcrafted_lr | 0.742 / 0.720 | 93.7% | 21% | +0.1 |
| handcrafted_hgb | 0.728 / 0.637 | 94.2% | 16% | +0.3 |
| **tfidf_lr** | **0.772 / 0.739** | **94.5%** | **19%** | **+0.8** |
| embedding_lr | 0.744 / 0.654 | 94.6% | 0%（τ = 1.0，全部交给 flash） | 0.0 |
| tfidf_multiclass | 0.751（多分类） | 93.7% | 25% | +0.3 |

**回答 RQ2：**

1. **TF-IDF + 逻辑回归最好**：两个分类器的 AUC 都是最高的，路由开销几乎为零（一次稀疏点积）。
2. **embedding 没有带来提升**：AUC 不比 TF-IDF 高，而且每个请求要多一次外部 API 调用（约 100 ms 加上费用），在高质量约束下，选出的 τ 甚至退化为"全部交给 flash"。因此不采用。
3. **多分类与级联效果相当**：多分类在同一约束下多省了一些成本，但准确率低 0.8 个百分点，相对凸包的优势也更小（+0.3 vs +0.8），两条曲线基本重合。级联的优势是模块化：新增模型时，不需要重新定义标签、重新训练整个模型。最终采用 tfidf_lr 级联。

### 4.4 RQ3：没见过的领域

law 和 history 两个学科从未参与训练。在这 246 题上，所有方案的 AUC 都在 0.47–0.53 之间，接近随机：路由器无法在这些题里区分难易。

但逻辑回归在这里**失败得很安全**：

| ood（246 题） | 准确率 | 全用 flash | 交给 flash 的比例 |
|---|---:|---:|---:|
| tfidf_lr，high 档 | 82.5% | 82.9% | 97% |
| handcrafted_hgb，high 档 | 77.6% | 82.9% | 65% |

逻辑回归对陌生输入给出的概率普遍偏低，过不了门槛，于是几乎全部升级给 flash，质量不下降；梯度提升树则对陌生输入过于自信，把 35% 的题留给了 lite，准确率下降 5.3 个百分点。这是选择逻辑回归的另一个理由。

**回答 RQ3：** 路由器的判断力不能迁移到新领域，但采用的模型会退回到强模型，保证质量。由于真实流量和基准题必然不同，需要一个机制在线上发现这种情况，这引出了 RQ4。

### 4.5 RQ4：漂移检测

每个 `model="auto"` 请求都会把以下信息写入 usage 记录：各模型的预测概率，以及 **OOV 比例**（题目中不在路由器词表里的词所占的比例）。检测脚本定期把一段时间内的线上分布与参考分布比较，使用 PSI（群体稳定性指数）：

- 参考分布取自 **test** 集，而不是 train 集：训练题的 OOV 比例恒为 0（词表就是从它们建出来的），正常的线上请求也有约 9% 的词不在词表中；
- PSI < 0.1 为稳定，0.1–0.2 为关注，≥ 0.2 为漂移。检测到漂移时脚本返回非零退出码，可以直接接入定时告警。

**演示**：通过网关发送两批各 100 个 `auto` 请求（演示时把最少样本数设为 100；样本少时 PSI 会被系统性放大，日常检测的默认最少样本数为 300）：

| 指标 | 参考均值 | 批次 A：test 题，均值 | PSI | 批次 B：law / history，均值 | PSI |
|---|---:|---:|---:|---:|---:|
| OOV 比例 | 9.2% | 9.1% | 0.013 | **16.7%** | **1.38** |
| P(local 答对) | 0.696 | 0.694 | 0.031 | **0.577** | **1.51** |
| P(lite 答对) | 0.901 | 0.898 | 0.003 | 0.877 | **0.86** |

批次 B 的三个指标全部判定为漂移。P(lite) 的均值只下降了 0.024，PSI 却达到 0.86：PSI 衡量的是整个分布形状的变化，只看均值是发现不了的。

**回答 RQ4：能。** 不熟悉的流量会同时体现在 OOV 比例和预测概率的分布上，检测器能把它和正常流量清楚地区分开，提示需要用新数据重新训练。

## 5. 结论

| | 结论 |
|---|---|
| **RQ1** | 能。balanced 档成本降低 45%、延迟降低 36%，保留 98.7% 准确率；economy 档成本降低 88%，45% 流量交给本地模型，比凸包高 4.0 个百分点。 |
| **RQ2** | TF-IDF + 逻辑回归最好且开销最小；embedding 没有带来收益；级联与多分类效果相当，级联更易扩展。 |
| **RQ3** | 判断力不能迁移到新领域，但逻辑回归会安全地退回到强模型，质量不下降。 |
| **RQ4** | OOV 比例和预测概率的 PSI 能清楚地区分新领域流量（0.86–1.51）与正常流量（0.003–0.031）。 |
